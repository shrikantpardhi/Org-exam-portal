# Design-Theme.md — Colored Theme Specification

**Project:** Smart Competitive Examination Platform
**Version:** 1.5
**Purpose:** The single theme reference for the AI implementation agent. Read this alongside `Design-Frontend.md`. Every color, every surface, every status has a documented token. Do not invent colors. Do not hard-code hex values in components. Every color decision on the platform flows from this file.

---

## 1. What this file governs

This file defines:

- The base color palette and design tokens
- Light and dark mode
- Semantic color mappings for status, state, and priority
- Examination-specific state colors
- Question palette colors
- Accessibility and contrast requirements
- The Tailwind configuration that produces these tokens
- CSS variable structure
- Component-to-color mapping
- Anti-patterns

It does not define typography, spacing, or radius. Those live in the base design system. This file is strictly about **color**.

---

## 2. The theme principles

1. **Color carries meaning.** Every color that appears in the UI maps to a documented semantic role. A green badge does not mean "green" — it means "success" or "published" or "answered." A red badge does not mean "red" — it means "error" or "rejected" or "expired."
2. **Contrast is non-negotiable.** Every foreground/background pairing meets WCAG 2.1 AA at minimum. Text on any surface is legible in both light and dark mode.
3. **Dark mode is a first-class citizen.** It is designed, not tinted. Every token has both a light and a dark value.
4. **No arbitrary colors in components.** Components use tokens. Tokens are the only path to color.
5. **The examination runtime receives extra care.** The palette must be readable on cheap screens, at distance, under stress, in bad lighting. Contrast targets are higher than the platform minimum.
6. **Semantic state is not decoration.** A status color that says "published" cannot be reused to say "in review" or "rejected." Each state has exactly one meaning.

---

## 3. The token architecture

Three layers, always applied in order.

```text
Layer 1 — Base palette
        Neutral and brand scales
        (gray-50 through gray-950, brand-50 through brand-950)
        |
        v
Layer 2 — Semantic tokens
        Named by role
        (surface, foreground, muted, primary, success, warning, error, info)
        |
        v
Layer 3 — Component tokens
        Named by component
        (button-primary-bg, badge-success-fg, palette-answered-bg, ...)
```

Components reference only Layer 2 and Layer 3. They never reference Layer 1 directly.

## 13. Dark mode design rules

Dark mode is not a tinted light mode. It is designed separately.

Rules:

1. **Never pure black.** The canvas is `neutral-950`, not `#000000`. Pure black is harsh and causes eye strain.
2. **Never pure white text.** The strongest foreground is `#f8fafc`, not `#ffffff`. Pure white on dark backgrounds causes halation.
3. **Reduce saturation of bright colors.** Status backgrounds that are bright in light mode are quieter in dark mode. The warning amber is `warning-400` rather than `warning-500`.
4. **Elevate with lighter surfaces.** In dark mode, "raised" surfaces are lighter, not darker. A modal sits at `neutral-800` on a `neutral-950` canvas.
5. **Soften borders.** Dividers use `neutral-800`, not `neutral-600`. Borders should be visible but not loud.
6. **Test on real screens.** Dark mode looks different on OLED (true black) vs IPS (grey blacks). Verify against both.

## 14. Accessibility requirements

Every color pairing meets WCAG 2.1 AA at minimum. The following pairs meet **AAA (7:1)** where the design allows.

### 14.1 Contrast targets

| Text type | Minimum ratio | Preferred |
|---|---|---|
| Body text | 4.5:1 | 7:1 |
| Large text (18pt+) | 3:1 | 4.5:1 |
| UI components | 3:1 | 4.5:1 |
| Graphical elements | 3:1 | 4.5:1 |
| Examination runtime | 7:1 | 10:1 |

The examination runtime is held to the highest standard because students use it under stress.

### 14.2 Non-color indicators

Color is never the only signal for a state. Every color indicator is paired with:

- A text label
- An icon
- A pattern (for charts)
- A numeric value

Example: a status badge shows "Published" in a green pill — the word "Published" is the signal, the green reinforces it.

Example: a chart uses color plus distinct line styles (solid, dashed, dotted) to distinguish series.

### 14.3 Focus indicators

Every focusable element shows a focus ring:

- **Light mode:** 2px outline, `brand-500`, 2px offset
- **Dark mode:** 2px outline, `brand-400`, 2px offset

The focus ring is never removed. `outline: none` is forbidden.

```css
    --border-focus: 129 140 248;           /* brand-400 */
    --border-danger: 248 113 113;          /* error-400 */

    /* Brand */
    --brand-primary: 99 102 241;           /* brand-500 */
    --brand-primary-hover: 129 140 248;    /* brand-400 */
    --brand-primary-active: 165 180 252;   /* brand-300 */
    --brand-subtle-bg: 30 27 75;           /* brand-950 */
    --brand-subtle-fg: 165 180 252;        /* brand-300 */
  }

  body {
    @apply bg-canvas text-default;
    font-feature-settings: 'cv02', 'cv03', 'cv04', 'cv11';
  }
}
```

Every component uses these variables indirectly through the Tailwind utilities (`bg-canvas`, `text-default`, `border-default`, etc.). No component references raw `neutral-*` or `brand-*` for surfaces. Base scales are used only for one-off accents where the semantic mapping does not apply (e.g., a gradient).

## 20. The theme switcher

The theme switcher offers three modes:

- **Light**
- **Dark**
- **System** (default — follows `prefers-color-scheme`)

Persist the user's choice in `localStorage` under `theme-preference`. Apply the theme before first paint to avoid a flash of unstyled content.

```tsx
// app/layout.tsx — inline script to apply the theme before hydration
const themeScript = `
  (function() {
    try {
      var stored = localStorage.getItem('theme-preference');
      var system = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light';
      var resolved = stored === 'light' || stored === 'dark' ? stored : system;
      if (resolved === 'dark') document.documentElement.classList.add('dark');
    } catch (e) {}
  })();
`;
```

The switcher itself is a three-way toggle in the header.

## 21. The examination runtime theme override

The runtime uses the platform theme but applies stricter contrast rules.

Rules:

- **No subtle colors for state.** The runtime uses the `-600`/`-700` variants rather than the `-subtle-bg` variants for critical state (timer, save, palette).
- **No animations that could distract.** State transitions are instant or fade only.
- **No gradients.** Flat colors only.
- **Larger touch targets.** Palette cells are at least 44x44 px.
- **High-contrast focus rings.** 3px, not 2px.
- **No dark mode until validated.** If the runtime is only validated in one mode at launch, only that mode is offered. Do not ship a runtime that "probably works" in dark mode.

## 22. Color anti-patterns

**Hard-coded hex in a component.**

```tsx
// Wrong
<div style={{ backgroundColor: '#4f46e5' }} />
```

```tsx
// Right
<div className="bg-brand-primary" />
```

**A status color used for decoration.**

```tsx
// Wrong — green here means "I like this section", not "success"
<SectionHeader className="text-success-600">Physics</SectionHeader>
```

```tsx
// Right
<SectionHeader className="text-strong">Physics</SectionHeader>
```

**Color as the only signal.**

```tsx
// Wrong — a colorblind user sees nothing
<span className="bg-success-500 w-2 h-2 rounded-full" />
```

```tsx
// Right — icon and text
<Badge variant="success">
  <CheckIcon /> Published
</Badge>
```

**Pure black or pure white.**

```tsx
// Wrong
<div className="bg-black text-white" />
```

```tsx
// Right
<div className="bg-canvas text-default" />
```

**Removing the focus ring.**

```tsx
// Wrong
<button className="outline-none" />
```

```tsx
// Right — use focus-visible and a visible ring
<button className="focus-visible:outline focus-visible:outline-2 focus-visible:outline-focus focus-visible:outline-offset-2" />
```

**Using a status palette for a non-status use.**

```tsx
// Wrong — amber means "warning", not "featured"
<div className="bg-warning-100">Featured Question</div>
```

```tsx
// Right — use brand for emphasis
<div className="bg-brand-subtle-bg text-brand-subtle-fg">Featured Question</div>
```

**Mixing dark mode colors into light mode.**

```tsx
// Wrong — this class bypasses the theme system
<div className="bg-neutral-900 text-neutral-50" />
```

```tsx
// Right — token that resolves in both modes
<div className="bg-surface text-default" />
```

## 23. Testing the theme

The theme must be verified in both modes at every review.

Mandatory checks:

- **Contrast:** A contrast checker confirms every foreground/background pairing meets WCAG AA. The examination runtime is checked against AAA.
- **Visual regression:** Screenshots of every major surface in both modes are compared against baseline.
- **Focus rings:** Every focusable element shows a visible ring in both modes.
- **Charts:** Series remain distinguishable in both modes and for colorblind users.
- **Palette:** All six palette states remain distinguishable in both modes.
- **Timer:** All timer warning colors remain distinguishable in both modes.
- **Empty and error states:** Every state renders correctly in both modes.
- **Skeleton:** Loading states animate correctly in both modes.

A theme bug is a release blocker when it affects the examination runtime.

## 24. Adding a new color

If a new color is needed:

1. **First ask: does an existing semantic token express this?** If yes, use it. Do not add a new color.
2. **If a new semantic token is needed, add it to this file first.** Name it by role (`bg-warning-surface`, not `bg-amber-50`).
3. **Define both light and dark values.**
4. **Define contrast ratios against every surface it will appear on.**
5. **Update the Tailwind config and CSS variables.**
6. **Add tests.**
7. **Only then use it in a component.**

Adding a raw hex to a component file is a code review rejection.

## 25. The theme principles summary

| Principle | Enforced by |
|---|---|
| Every color maps to a documented role | This file, code review |
| Every token has a light and dark value | CSS variable layer |
| Every foreground/background pair meets AA | Contrast test suite |
| The examination runtime meets AAA | Runtime contrast tests |
| Color is never the only signal | Accessibility tests |
| No hard-coded hex in components | Lint rule, code review |
| Dark mode is designed, not tinted | Design review |
| Focus rings are always visible | Accessibility tests |
| Charts are colorblind-safe | Chart palette |
| Palette states are distinguishable in both modes | Palette contrast tests |
