## The rule

A caller may grant only codes it currently holds. `UNBOUNDED_PERMISSION_ASSIGN` satisfies both this
rule and the reserved set, so an operator has one knob.

## D-08 overlap

Task 4 closes D-08's **step 1** as a side effect: the second call of the reproduced escalation
(`PUT /roles/<ELEV_TEST>/permissions {ADMIN_ROLE_ASSIGN}`) now returns 403 because the actor does not
hold `ADMIN_ROLE_ASSIGN`. What remains for Task 8 is Rule A — refusing the *assignment* of a role that
is already escalated to an assigner who cannot see that it is.

## Behaviour change for operators

An ADMIN can no longer delegate a permission it has not been given. This is the intent, but it must be
in the release notes: a deployment relying on an ADMIN seeding roles with codes it does not hold will
now fail loudly instead of silently succeeding.

## Residual

The rule reads the caller's effective permissions, which are cached for 5 minutes. A stale cache can
briefly allow a grant of a code the caller no longer holds. Accepted: the window is bounded by the
TTL and by per-user eviction on every role change, and it is strictly smaller than the pre-fix
exposure, which was unbounded and permanent.
