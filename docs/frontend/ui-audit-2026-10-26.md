### Specification conformance found during implementation

`specs/Design-Theme.md` §21 turned out to state rules the code violated, which changed two findings
from a matter of preference into a defect:

| Spec rule | Was | Now |
|---|---|---|
| No gradients. Flat colors only. | landing hero used `bg-gradient-to-b` | flat `bg-surface` |
| Palette cells are at least 44x44 px. | exam palette cells were 36 px (`size=sm`) | `h-11` (44 px) |
| No dark mode until validated; only that mode is offered. | toggle offered an unvalidated dark theme | light only |

### Regression found and fixed during this work

Wrapping the 13 raw tables in a `role=region` wrapper initially moved each table's `aria-label` onto
the wrapper, which removed the table's accessible name and broke three existing tests
(`findByRole(table, { name })`). Caught by the suite; fixed by keeping the label on the `<table>` and
leaving the wrapper as a plain keyboard-scrollable container. This is why the table change ran against
the full suite rather than in isolation.
