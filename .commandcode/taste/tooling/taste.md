# Tooling taste
- Builds the backend with the Maven wrapper on this Windows host (`backend\mvnw.cmd`); the offline flag `-o` works for `test-compile` and `test`, but `package` fails offline because `maven-jar-plugin` is absent from the local repository — re-run without `-o` so the artifact can be fetched. Confidence: 0.8
- Surefire `-Dtest` package wildcards (e.g. `-Dtest=com.company.exam.integration.delivery.*`) do not match in this repo; lists test class names explicitly instead of relying on the wildcard. Confidence: 0.8
- In Mockito unit tests here, constructs the SUT in `@BeforeEach` rather than in a field initializer (mocks are injected only after field initialization runs), and never mixes raw values with matchers inside one call. Confidence: 0.8
- Asserts `background_job.parameters` (jsonb) by id substring rather than by exact `"key":"value"` strings — PostgreSQL normalizes the stored JSON (it inserts a space after the colon). Confidence: 0.8
- In the integration harness, creates the student before `prepareAttempts(...)` (candidate population), and publishes the answer key before the submit that is expected to enqueue an `EVALUATION` job. Confidence: 0.75
- Knows the async evaluation worker is disabled by default (`app.evaluation.worker.enabled=false`), so `EVALUATION` background jobs stay `QUEUED` and their payload is directly observable in integration tests. Confidence: 0.8
- Maven is not installed on this Windows host (no `mvn`/`mvn.cmd` on PATH nor anywhere under C:/ or D:) — build with the wrapper `backend\mvnw.cmd` and don't spend turns hunting for a system Maven. Confidence: 0.8
- PowerShell `Set-Content`/`Out-File` here (PS 5.1) writes ANSI and silently corrupts UTF-8 markdown — backticks get swallowed as escape characters and em-dashes are mangled — so edit UTF-8 docs with the file read/edit/write tools (or `Set-Content -Encoding UTF8`), then verify the result has no U+FFFD replacement characters or mojibake. Confidence: 0.85
- For long Maven runs, redirect the output to a log file and grep that (`.\mvnw.cmd "test" *> "$env:TEMP\run.log"` then `Select-String -Pattern 'Tests run:|BUILD'`) because direct console output gets truncated before the summary lines. Confidence: 0.75
- In PowerShell, pass Maven goals and properties as quoted strings when they contain commas or dashes (`.\mvnw.cmd "test" "-Dtest=A,B"`); an unquoted `-Dtest=A,B` is mangled by the shell. Confidence: 0.7
- Background Maven runs launched through `cmd` produce an empty captured log, and the `%COMMANDCODE_SCRATCHPAD%` env var does not expand inside a `cmd` redirect — run them from PowerShell with `Out-File -FilePath "<absolute path>" -Encoding utf8`, then grep that file for `Tests run:` / `BUILD`. Confidence: 0.8
- The backend integration suite uses embedded Postgres, so `mvnw.cmd test` needs no Docker/Testcontainers daemon — but the embedded DB and the surefire runs take minutes, so run them in the background and poll the log. Confidence: 0.8
- The Java toolchain on this host is JDK 25 (`JAVA_HOME=C:\java\jdk-25.0.4.1`) while the project compiles with `--release 21`. Confidence: 0.75
- On this Windows host, a long Maven run's exit code is captured reliably with `Start-Process -FilePath ".\mvnw.cmd" -ArgumentList "test","-Dtest=Foo" -Wait -PassThru -NoNewWindow -RedirectStandardOutput "<log>" -RedirectStandardError "<err>"` followed by `Write-Output "EXIT_CODE=$($proc.ExitCode)"`, then grepping the log for `Tests run:`/`BUILD` — the plain `cmd` background redirect produced an empty captured log before. Confidence: 0.75
- When `read_file` returns nothing for a path already read earlier in the session (it deduplicates), dump the file with `grep` using `pattern: "^.*$"` (optionally with `offset`/`head_limit` for long files), or use `git --no-pager diff -- <path>` to see uncommitted modifications. Confidence: 0.7
- Background shell runs are polled with the `shell_output` tool (`id` plus `wait: "output"` and a `timeout_ms` budget) to wait out a long Maven run without blocking the turn; a foreground `powershell` Maven run can be killed part-way when the tool timeout elapses, so a full suite is relaunched with `run_in_background: true` and polled to completion. Confidence: 0.7
- The integration database is shared across the whole suite, so list assertions must be relative (containment of a specific id, or a filtered subset) rather than absolute totals — an absolute `$.data.length()` assertion failed because rows from other tests are present. Confidence: 0.75
- The per-class Surefire failure detail is at `backend/target/surefire-reports/<fully.qualified.TestClass>.txt`; read it with the file-read tool to see the failing assertion (a `type` shell command in that directory produced nothing). Confidence: 0.7
- Verifies module boundaries with a scripted repo-wide import scan instead of spot greps: a PowerShell loop over `backend\src\main\java\com\company\exam` that derives each file's owning module from its path, matches `import com.company.exam.([a-z]+)\.(repository|entity)\.`, and flags any import whose module differs — excluding shared packages (`common`, `config`, `infrastructure`) and reporting cross-module `repository` imports separately from `entity` imports. The backend has 11 modules: identity, academic, content, assessment, delivery, evaluation, analytics, commerce, communication, administration, reporting. Confidence: 0.75

- There is no static OpenAPI artifact in this repo — springdoc generates the spec at runtime and GAP-028 records that the generated document is not retained as an artifact; no controller declares `@ApiResponse` (verified: zero occurrences), so error codes are not enumerated in any spec file.
